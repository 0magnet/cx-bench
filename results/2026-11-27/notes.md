# Notes on the 2026-11-27 native results

`results.md` and `chart.png` are generated by `harness report` from
`raw.jsonl`, every run of `harness measure -forms native`. The machine is an
x86-64 desktop with 8 logical CPUs and 16 GB RAM, running its owner's
desktop session beside the benchmarks, so the one minute load average was
1.4 to 4.7. skycoin-cx was at commit 01deb81a.

## Best of each language, time per round over C

| benchmark | best CX | best Lua | best Go |
|---|---|---|---|
| count | cx-image 75.7 | luajit 3.93 | tinygo 0.95 |
| fib | cx-llvm 1.19 | luajit 2.72 | tinygo 0.96 |
| array | cx-llvm 1.00 | luajit 1.04 | tinygo 1.02 |
| struct | cx-llvm 1.08 | luajit 14.6 | tinygo 1.02 |
| memtest | cx-llvm 1.04 | luajit 3.66 | tinygo 1.10 |
| primes | cx-llvm 1.00 | luajit 1.94 | tinygo 1.02 |
| ackermann | cx-llvm 1.72 | luajit 2.65 | tinygo 0.92 |
| digitalroot | cx-llvm 0.91 | luajit 7.33 | tinygo 0.83 |
| factorialiter | cx-llvm 1.00 | luajit 16.5 | tinygo 1.25 |
| factorialrec | cx-llvm 2.82 | luajit 25.2 | tinygo 1.00 |
| structs | cx-llvm 1.18 | luajit 2.44 | tinygo 1.22 |
| structserialize | cx-llvm 4.75 | luajit 105 | tinygo 1.55 |

* cx-llvm is within the noise of C on array, memtest, primes, digitalroot
  and factorialiter. It is slower than C beyond the noise on fib (1.19),
  ackermann (1.72), factorialrec (2.82), structs (1.18) and
  structserialize (4.75): the calls and the byte buffer cost more.
* cx-llvm count is precomputed: LLVM sees the zero of the CX program as a constant
  (the vm subset has no input), computes the loop at build time and removes
  it, so a round costs 1 ns. It is marked
  precomputed and left out, and the best CX for count is cx-image, 34 ms a
  round, against 0.45 ms for C.
* cx-vm and cx-image are 14 (primes) to 530 (struct) times C, and 4000
  times on structserialize. They are 1.2 to 6 times slower than Lua 5.4
  (digitalroot 57 ms against 47 ms, fib 14.7 ms against 7.4 ms, array
  2.4 ms against 0.41 ms).
* gc Go is 1.6 to 5 times TinyGo on fib, ackermann, factorialrec and
  memtest, and 21 times on structserialize. TinyGo is the best Go on every
  benchmark.

## Sensitivity

* Run to run spread over five runs: median 3.4 percent over 130 form and
  benchmark pairs, above 10 percent for 12 of them, the worst C ackermann
  (30.5), gopher-lua count (37.8), cx-vm factorialrec (36.3), python
  structserialize (35.7) and lua 5.4 factorialiter (34.1). These moved with
  the desktop load.
* Code placement, five runs of a second build with the code moved, on c,
  go, tinygo, cx-vm, cx-image and cx-llvm: above 5 percent for 14 of 73
  pairs. The largest are cx-vm count 27.5, cx-image memtest 21.0, c
  digitalroot 13.0 and cx-image factorialiter 11.6. A difference between
  cx-vm and cx-image smaller than that is not a result.
* The size sweep (whole run per round at size/8, /4, /2 and the size) is
  flat within a few percent for the compiled forms: start up is amortized
  at the sizes used. The sizes reach 2 s per run, and the empty program of
  every form is under 52 ms, so every run is over 100 times its start up.
* Server mode, three runs of one process, gives the same time per round as
  the one-shot runs within the spread. The first run is not measurably
  slower: no form here has a warm up that matters at one second a pass.
* The programs' own -time=us loop times agree with the harness markers to
  0.1 percent for every compiled form and Python. Lua 5.4, 5.5 and
  gopher-lua read 0.4 to 3.6 percent low, as os.clock is CPU time.

## Phases

Load, process start to S, is at most 1.5 ms for every compiled form and for
Lua and LuaJIT, 17 ms for Python and 2.7 ms for gopher-lua. The Lua 5.1
driver of gopher-lua builds its byte XOR table after S, 49 ms counted in
Loop 1. Loop 1 and Loop 2 are within the spread of each other except LuaJIT primes
and TinyGo structserialize, which differ by 3.4 and 1.7 percent: no form
gets measurably faster on the second identical pass. Finish is under 1 ms,
except LuaJIT primes (15 ms, the collector at exit).

The CX forms write no markers, so their Load is the whole run of the
empty program (cx-llvm 0.7 ms, cx-image 2.1 ms, cx-vm 13.8 ms, parsing
included) and the passes are split evenly. They are marked est.

## Not measured

* Brave: the browser forms were not run.
* wasmtime: the build host with wasmtime is off at night.
* Lua 5.1 primes, factorialiter and factorialrec: gopher-lua has no 64 bit
  integers.
* Bash: left out, see the README.
